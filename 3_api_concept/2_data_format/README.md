## Response Section

JSON เป็นข้อความที่มีชื่อฟิลด์อยู่ในข้อมูล เปิดอ่านได้จากเบราว์เซอร์และใช้งานกับภาษาโปรแกรมส่วนใหญ่ได้ทันที จึงเหมาะกับ public API และการตรวจสอบคำขอ ข้อจำกัดคือชื่อฟิลด์ซ้ำทำให้ payload โต และ JSON เองไม่ได้บังคับชนิดข้อมูลระดับสัญญา เช่น รูปแบบวันที่ ต้องตรวจด้วย serializer หรือ JSON Schema

Protocol Buffers ใช้ไฟล์ .proto กำหนดชนิดข้อมูลและหมายเลขฟิลด์ แล้วเข้ารหัสเป็นไบนารี เหมาะกับระบบภายในที่รับส่งข้อมูลจำนวนมากและต้องการ client หลายภาษาที่สร้างจากสัญญาเดียวกัน ข้อแลกเปลี่ยนคือผู้พัฒนาต้องจัดการ schema และเครื่องมือสร้างโค้ด และต้องมีตัวถอดรหัสเพื่ออ่านข้อมูล ระหว่างการอัปเกรดควรสงวนหมายเลขฟิลด์ที่เลิกใช้เพื่อให้ client รุ่นเก่าตีความข้อมูลได้ถูกต้อง

สำหรับ API โรงเรียนที่ต้องเปิดทดสอบผ่านเบราว์เซอร์ ผมเลือก JSON หากเป็นการซิงก์ข้อมูลบุคลากรปริมาณมากระหว่างบริการ ผมจะวัดขนาดหลังบีบอัดและเวลา encode/decode ของทั้งสองแบบจากข้อมูลจริงก่อนเลือก
